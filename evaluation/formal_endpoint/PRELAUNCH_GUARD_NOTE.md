# Prelaunch Environment-Path Gate Record

The environment-path identity gate stopped the first parallel launch attempt before any formal task completed. Windows `ProcessPool` subprocesses inherited a module-search ordering in which the directory containing the pure rotation-span helper preceded the formal environment. They consequently attempted to load a same-named environment file from another research snapshot. The evaluator immediately failed closed when it detected that the loaded environment path differed from the formal environment path. At that point, `completed_tasks=0`; no formal task JSON or NPZ had been created, and no training checkpoint had been modified.

The launch-level record from that failed attempt is preserved under the old `evaluation/` directory beside this file and is not part of the formal results. After the fix, the helper directory is visible only temporarily while the two pure rotation functions are imported, and the formal-training directory is forced to the front of the module-search path. Every subprocess still verifies the actual loaded environment-file path and its SHA-256 digest. The sole formal output root is frozen as `evaluation_final/`, and the evaluator script's own SHA-256 digest is included in the start marker, every task signature, the study manifest, and the final validation receipt.
